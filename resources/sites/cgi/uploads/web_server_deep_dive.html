1
You type a URL → DNS lookup
Your browser asks a DNS server: "What is the IP address of mysite.com?" The DNS returns something like 104.21.55.3. This is like looking up a phone number in a directory.
Browser: "Where is mysite.com?" DNS server: "Its IP is 104.21.55.3"
2
TCP connection is opened
Before sending any data, browser and server do a 3-way handshake to open a reliable connection. For HTTPS, a TLS handshake follows for encryption.
Browser → Server: SYN Server → Browser: SYN-ACK Browser → Server: ACK ✓ Connection open
3
Browser sends HTTP request
The browser sends a structured text message to port 80 (HTTP) or 443 (HTTPS) on the server's IP address.
GET /index.html HTTP/1.1 Host: mysite.com Accept: text/html User-Agent: Mozilla/5.0
4
Server reads & processes the request
The web server software (Nginx, Apache…) receives the raw bytes, parses the method, path, and headers, then decides what to respond with — a file, an error, or a redirect.
Method: GET Path: /index.html Host: mysite.com → Look for file at /var/www/html/index.html
5
Server sends HTTP response
The server sends back a status line, headers, and the requested content (HTML, JSON, image bytes, etc.).
HTTP/1.1 200 OK Content-Type: text/html Content-Length: 4823 <!DOCTYPE html><html>...
6
Browser renders the page
The browser parses HTML, discovers CSS and JS files, fires more GET requests for each one, and finally paints the page on your screen. The server remains stateless — it forgets everything.
An HTTP request is just plain text — a structured message with a start line, headers, a blank line, and an optional body.
HTTP Request anatomy
POST /login HTTP/1.1 ← Start line (method + path + version) Host: mysite.com ← Headers start Content-Type: application/json Content-Length: 38 Authorization: Bearer eyJ... ← Blank line separates headers/body {"email":"a@b.com","pass":"1234"} ← Body (only on POST/PUT/PATCH)
HTTP Response anatomy
HTTP/1.1 200 OK ← Status line Content-Type: text/html; charset=utf-8 Content-Length: 1234 Set-Cookie: session=abc123; HttpOnly Cache-Control: max-age=3600 <!DOCTYPE html><html>...</html> ← Body (the actual content)

Static content
Files served exactly as stored on disk. Same response for everyone, every time.
html Page structure css Styles js Client scripts png/jpg Images
GET /logo.png → read file → send bytes
Dynamic content
Response is generated on the fly — different per user, per time, per data.
PHP Server language Node.js JavaScript Python Django/Flask DB Query results
GET /dashboard → auth check → query DB → build HTML → send response
A single website often uses both — static files (CSS, images) served instantly from cache, and dynamic routes (login, feed) generated per request.
Why you can't skip the web server
Always listening
Waits on port 80/443, 24/7, for any incoming connection
Handles concurrency
Manages thousands of requests at once via threads or async I/O
Secures with HTTPS
Manages TLS certificates and encrypts all traffic
